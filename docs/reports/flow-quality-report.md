# Flow quality, reliability, speed and cost report

Flow version `2.6.0`. Generated by `python3 scripts/flow_report.py --write` from repository data only. No model was called to produce it, so it cost nothing beyond a local run.

## What this report can and cannot say

It measures **Flow as a piece of software and a body of instructions**: do its gates pass, how stable is its CI, how fast is its pipeline, and how much context does it add. It does **not** yet measure **Flow as a way of working**: whether an agent using Flow finishes real tasks better, faster or cheaper than the same agent without it. That needs paid, repeated, paired model runs, planned in [paid-run-plan.md](paid-run-plan.md) and not yet approved or run. Until then no claim about task quality, speed or cost savings is made, in line with the release records.

Every number below is labelled `MEASURED`, `PARTIAL` (a real number with a stated limit) or `NOT_RUN`.

## Quality

- Structure validators (`validate_skills.py`, `--suite`): pass on this checkout.
- Test suite: 564 test cases defined across 37 files (counted statically; the run result is under Reliability).
- Records: 35 release records and 7 evaluation records in `docs/`.
- Mutation check of the shell installer tests: 30 of 34 mutants caught. The release record says why the other four were not. ([docs/TESTING.md](../../docs/TESTING.md))
- Behavior evaluation of the 1.6.1 candidate against the 1.6.0 baseline ended in a rejected promotion. Paired simulations scored 95/96 (baseline) and 94/96 (candidate); the sealed holdout scored 15/16 and 14/16. This is a recorded null result, not a quality gain. ([docs/releases/v1.6.1.md](../../docs/releases/v1.6.1.md))
- **Not measured:** whether work done with Flow is more correct, more complete or better verified than work done without it.

## Reliability

CI snapshot of the `Validate` workflow, captured 2026-10-23 from the GitHub Actions API. Pass rate = success / (success + failure); cancelled runs are listed apart.

| Scope | Runs | Success | Failure | Cancelled | Pass rate |
|---|---|---|---|---|---|
| All | 225 | 180 | 18 | 27 | 90.9% |
| Pushes to `main` | 74 | 69 | 1 | 4 | 98.6% |
| Pull requests | 149 | 110 | 16 | 23 | 87.3% |

Failures on pull-request branches are mostly the gate doing its job during development, so the pull-request pass rate is not a defect rate. The `main` row is the stricter signal. The snapshot keeps only the final attempt of each run.

Local full suite (`Linux`, Python 3.13.17, 4 CPUs): **563 tests, exit 0** (0 failures, 0 errors, 11 skipped) in 744 s on base commit `e19c625190` plus the uncommitted report changes. One run on one machine; wall time depends on load, and the suite includes a recursive archive acceptance test. Two earlier runs on a shallow clone failed (3 tests, then 1): the second was the portfolio test that needs full git history, and the three names of the first run were not captured. The run above is on a full clone.
- Full deterministic suite at 2.5.0: 544 tests, exit 1 with two failures and five skips. Both failures came from a stale extracted plugin in an ignored backup directory, not from the source. ([docs/releases/v2.5.0.md](../../docs/releases/v2.5.0.md))
- The two failed tests passed on rerun with no source change, after the stale directory was moved out of the checkout. ([docs/releases/v2.5.0.md](../../docs/releases/v2.5.0.md))
- The repository's own rule: a single model run says nothing about reliability. ([docs/releases/v2.2.0.md](../../docs/releases/v2.2.0.md))
- **Not measured:** how often an agent following Flow completes a task correctly across repeated runs. Single runs do not estimate it.

## Reproduce

```bash
python3 scripts/flow_report.py --check     # fail if this file is stale
python3 scripts/flow_report.py --write     # regenerate it
python3 scripts/flow_report.py --run-tests --write   # also re-run the full suite (about 20 minutes)
```

The CI snapshot is stored in `docs/reports/data/ci-validate-runs.json` and has to be refreshed from the GitHub Actions API by hand; the script never touches the network.
