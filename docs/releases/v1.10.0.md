# Version 1.10.0 - session care, naming and delegation boundaries

This release extends the existing Sessions and Ultra contracts without adding a
new permanent skill, visible conversation or background daemon.

## Scope

- Explicit NoBrainer.Tech Flow entry invokes startup naming and health
  assessment using verified session metadata where the host provides it.
- A deterministic title helper formats the observed start date and timezone but
  never creates or renames a session.
- Context pressure and a materially smaller startup can qualify a safe health
  rotation without inventing billing or token-savings proof.
- Native subagents are the bounded delegation path. Visible conversations require
  an explicit owner request or authorized MAIN restart.
- Maintained public language uses NoBrainer.Tech Flow; technical identifiers and
  package compatibility remain unchanged.
- `nobrainer-wiki` records adoption gates for external memory services: scope,
  provenance, freshness, conflict handling, deletion/export, privacy, cost and
  file fallback.

## Verification boundary

The release candidate passed both validators, 165 deterministic tests,
session-title and restart-gate tests, syntax checks, whitespace checks and a
staged secret scan. The actual client startup and native fresh-session takeover
remain host-specific; unsupported hosts use a manual handoff. No universal
context-saving, billing, model-quality or automatic-transport claim is made.

## Rollback

The rollback anchor is the published `v1.9.0` tag. Revert to that exact source
after verifying the tag and rerun its validators. Existing package/plugin IDs,
skill paths and compatibility aliases remain unchanged.
