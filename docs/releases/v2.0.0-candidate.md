# nobrainer-tech-flow 2.0.0 candidate

Status: **owner review required**. This document is a proposed release note,
not proof of a published tag, client upgrade or runtime behavior.

nobrainer-tech-flow now uses `nobrainer-tech-flow` as both its repository ID
and its explicit entry skill. The former `nobrainer-ultra` entry is recognized
as a migration source, not a new invocation. Public package and plugin IDs
also use `nobrainer-tech-flow`; existing client registrations need a reviewed
one-time migration to avoid loading old and new adapters together.

The eighteen-skill portfolio adds `nobrainer-auto-fine-tune`. It selects
worker routes from the models and limits the active client actually exposes,
benchmarks only when a bounded comparison is worth its cost, and preserves
the user's selected MAIN model and effort. Project start now connects a
short-term goal to the owner's longer-term direction, checks the existing
layers and wiki, and keeps session takeover and archival evidence separate.

The installer previews and applies a concise global instruction block for
Codex, Claude Code, OpenCode or Copilot CLI. An installed Flow skill checks
the latest stable release once per active day, with honest offline states.
Safe auto-upgrade and session restart are explicit personalization options;
an inactive client still needs an external scheduler for unattended checks.
