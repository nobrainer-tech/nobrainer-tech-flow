# nobrainer-tech-flow 2.7.0: owner requests go into the goal file

Release date: 2026-10-25.

This release changes workflow guidance, the optional Claude Code guards,
`nobrainer-team`, `nobrainer-security` and `nobrainer-build`. The setup record and the module set (eighteen) do not change.

## What changes

- **Owner requests go into the goal file as they arrive.** In
  `skills/nobrainer-tech-flow/SKILL.md` the detailed-ledger gate has a new condition: the
  owner keeps adding requests mid-run in one long conversation. A new section of
  `references/long-run-state.md`, "New owner requests", sets the rule. While the ledger is
  active, the agent records each new request or idea before it continues any work, even
  when the request is deferred. The row quotes the owner's words (minus any secret) and
  carries the date and the status `PENDING`, or `READY` when nothing blocks it. When the
  gate first passes mid-conversation, earlier unfinished requests are backfilled. Rows are
  reconciled at every checkpoint, after compaction and at closeout, and none is silently
  dropped. At closeout each row is `ACCEPTED`, `STOPPED` with the owner decision that
  stopped it, or visibly open with its next step. The default task-local goal file is
  `.nobrainer/goal.md`, which the context inventory already searches; it should not be
  committed to a public repository. The short restatements of the gate in
  `references/routing.md`, `references/setup.md`, `AGENTS.md`, `CLAUDE.md` and the
  README say the same.
- **The guards point back to the goal file after compaction.** The optional Claude Code
  guards gain a fourth hook, SessionStart with the matcher `compact|resume|clear`. It
  tells the agent to re-read up to three active Flow goal files: files with a `GOAL_ID:`
  line and a `STATUS` other than `COMPLETE` in the project root, `tasks/`, `docs/` or
  `.nobrainer/`. It prints only each path and a known `STATUS` word, never other
  goal-file text. It follows no symlink, skips unusual file names, stops after 5,000
  folder entries or 200 files, and prints nothing on any error.
  `scripts/install_guards.py` now reports an install from an earlier version as an
  update. If you already use the guards, update your Git checkout to 2.7.0 first, so the
  hooks' `flow_guard.py` knows the new mode, then preview the change with
  `python3 scripts/install.py --client claude --guards`, apply it with `--apply` and
  restart Claude Code. Until then the three earlier hooks keep working unchanged. The hook
  only finds goal files that already exist; it does not write one.
- **Team uses task-local specialists, not third-party skills.** `nobrainer-team` no
  longer searches for, downloads, installs or runs external skills, and it writes into no
  client's skill folder. When a capability gap remains after curated skills, installed
  skills, project tools and bounded research, MAIN writes a specialist brief (role,
  method from project docs or verified primary sources, allowed actions, write scope,
  acceptance and report) for a native worker. The brief stays in the task plan and is
  discarded afterwards. The module's description now says "task-local specialist briefs".
- **A clean security result needs more than one pass.** In
  `skills/nobrainer-security/SKILL.md` one model pass counts as a sample of the scope, not
  as coverage. Before `CLEAN`, at least one more independent pass starts from a different
  entry point, trust boundary or data-flow direction; the review stops when a pass adds no
  new verified finding and reports how many passes ran. After a fix, when the defect was
  public or reachable before it, the agent checks the available logs or other evidence for
  exploitation during that exposure window, or lists the window under
  `UNTESTED_OR_INACCESSIBLE_SURFACE`. In `references/delivery.md` the security-sensitive
  paths that need an independent review and stay owner-gated, however small the diff, now
  name authentication, permissions, payments and personal data.
- **Stale conventions are reported, not followed silently.** In
  `skills/nobrainer-build/SKILL.md`, when instruction files or docs describe a coding
  convention that the existing code does not follow, the agent follows the convention the
  code uses, unless the instruction is an explicit owner rule or names a deliberate
  migration, and lists each disagreement in its final report. Owner rules on safety,
  authority and workflow always apply.
- **Accurate install documentation.** The README lists the free remote MCP server
  (`https://mcp.nobrainer.tech/mcp`, no sign-in, stateless, six read-only tools) as a
  sixth channel and says it does not install the eighteen modules. `docs/CHAT_PLUGINS.md`
  and `docs/INSTALL.md` now say the npm package is published.
- **Test fixes.** The bounded-runner interrupt test waits until the child's pid file
  holds a number, not only until it exists, which removes an intermittent CI failure.
  A duplicate GitHub transport test that shadowed another one was removed.

## The remote MCP server

The MCP server in `mcp/` is deployed separately and is not part of the npm package.
Since 2.6.0 it returns a goal-file block with a renewed contract token when
`get_flow_step` is called with a contract token and `event: "resume"`, and a scheduled, read-only workflow
warns three days before the bundled model-advisor benchmark snapshot expires. Its
guidance cards are still pinned to 2.6.0 and move to this release in a separate change
after the tag.
