# nobrainer-tech-flow 2.0.2 verification record

Source version: 2.0.2. Publication is a separate check against the public tag
and release archive; this document alone does not establish distribution.

2.0.2 builds on the [2.0.1 record](v2.0.1.md): everything in it is part of this
release. It adds one script and fixes what an independent review of 2.0.1 found.
It adds no skill (the portfolio stays eighteen), and no skill text, adapter,
manifest or hook changes.

## What changed

One-command installer

- `python3 scripts/install.py --client claude` previews, `--apply` installs and
  `--undo --apply` reverses, for `claude`, `codex`, `opencode` and `copilot`. It
  asks nothing.
- The preview names the source commit (and "local changes"), how many skills it
  would link and where, and prints the exact text it would write to the client's
  global instruction file. It writes nothing.
- It is a front end over the guided setup with every skill selected, so the client
  paths, the `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `XDG_CONFIG_HOME` rules, the
  conflict refusal and the rollback state are the ones that already existed.
  `--undo` therefore also reverses a guided setup, and the other way round.
- A target that is not a link to this checkout is refused with the reason and
  nothing is written. A machine that cannot create symbolic links (Windows without
  Developer Mode) is told so before anything is written.
- It never grants an authorization. Earlier auto-update, session-restart and
  wiki-root settings are kept as `--keep-options` keeps them.
- Limits: links only (copy installs, subsets, the shared `agents` folder and other
  clients stay with the individual scripts), and the guided setup's recommendation
  answers are filled with fixed values that this run ignores.

Fixes from the independent review of 2.0.1

Each has a regression test that fails against the 2.0.1 scripts.

- An environment variable that the selected client never reads (a literal
  `XDG_CONFIG_HOME=~/.config` with Claude Code, a relative `CODEX_HOME` with
  Copilot) stopped every client and made a finished setup impossible to undo. Only
  the variable the client reads is checked now. A value is used exactly as written
  (it used to be trimmed); only a blank one counts as unset.
- A grant could be forged under `--keep-options` from a `--wiki-root` path that
  carried a line-separator character (U+2028, U+0085, U+001C and others), because
  grant lines were found with `str.splitlines`. A grant is now a whole line ending
  at `\n` or `\r\n`, and a preference or wiki path must be one printable line.
  Wording that no longer matches an earlier grant (a trailing space, a re-wrapped
  line) is not kept, and the run now says so and names the flag.
- The check for a Claude `@` import of the Codex file mistook double-backtick code
  spans, a fence inside a longer fence, a stray ` ``` ` in prose, a code span that
  wraps a line, an unclosed comment, a Windows backslash spelling and raw HTML for
  an import, so the block was silently not written. The check is rewritten to hide
  everything that might be code, HTML or a paragraph it cannot read. A missed
  import only writes a second copy; a guided setup recorded earlier for the Codex
  file now asks for `--rollback --apply` before it continues, instead of stopping
  with an unexplained mismatch.
- On Python 3.13 a destination that is a symlink loop was accepted (`resolve()` no
  longer raises); it is reported again.
- Copy mode ignored every `.pyc` and any directory named like litter, so a planted
  `json.pyc` next to a script (importable, and it shadows the standard library) was
  reported as an identical copy. Only `__pycache__` directories and `.DS_Store` and
  `Thumbs.db` files are ignored now.
- A home path that is not valid UTF-8 finished a setup that could not then be
  undone (the rollback state is read from printed paths); it is refused before any
  write. A relative `HOME` is refused too instead of writing inside the checkout.
- End of input at the interactive selection prompt ends the run instead of raising.
- The 2.0.1 statement that Claude Code "does not accept" a relative or `~`
  `CLAUDE_CONFIG_DIR` was wrong: Claude Code 2.1.284 creates the directory named by
  a relative value in its working directory and takes `~` literally. The installer
  still refuses relative values, because it runs from the checkout and cannot know
  what the client means, and says so correctly now.

Documentation and gates

- README and `docs/INSTALL.md` lead with `install.py`; the erratum for the 2.0.1
  statements above is at the top of its record.
- Tests: `tests/test_one_command_installer.py` (real scripts against a private
  home; each check was verified against a mutated script that must fail it), the
  regression tests above, and two checks that were vacuous in 2.0.1 now fail
  when the property they name is removed (chunked digests, the closed-stdin guard).
- CI runs the installer tests in the Windows job and the whole suite on Python 3.13.

## Reproduce the repository checks

From the exact reviewed release checkout, run:

```sh
python3 scripts/validate_skills.py --suite
python3 -m unittest discover -s tests -q
```

## Evidence limits

These checks establish local helper behavior, source contracts and the client
readbacks named in the [compatibility record](../COMPATIBILITY.md), which was made
against the 2.0.1 adapters that this release leaves unchanged. They do not prove
that a client routes a task through Flow, that a model followed a skill, or that
Cursor, Gemini CLI, Kimi Code, OpenCode or Pi accept the adapters at runtime. No
client was read back on an install made by `install.py`.

- The import check was compared, outside the suite, with Claude Code 2.1.284's own
  extraction (its `@` regular expression over the tokens of a Markdown lexer that
  skips code and HTML, re-implemented in Node from the function in the binary with
  `marked` 15.0.12; the lexer version inside the binary was not checked) on 360 000
  random documents built from hostile constructs: none was a document where the
  installer saw an import and Claude Code did not. About two thirds of the
  documents Claude Code imports from were recognised; the rest count as "not an
  import" on purpose. The experiment needs Node and network and is not part of the
  suite.
- The Windows job runs the installer tests on a runner that can create symbolic
  links; behaviour on an account that cannot is covered by a mocked probe only.
- Known gaps that this release does not address are the cost of starting Flow on a
  trivial task, the worktree-per-task default, and the differences between the Flow
  and Dispatcher ledgers.
