# Version 1.11.0 - Codex project context

This source release adds one original, Codex-specific skill without copying a
third-party orchestrator or changing the existing NoBrainer.Tech Flow lifecycle.

## Scope

- `nobrainer-codex-context` owns project-local Codex instruction discovery and
  setup: root markers, `AGENTS.override.md`/`AGENTS.md`, configured fallback
  names, byte-budget/truncation risk and post-edit readback.
- The bundled Python probe is read-only and returns a machine-readable context
  inventory. It is not a client hook and does not mutate `~/.codex/config.toml`.
- Setup may add or update one `NOBRAINER-CODEX-CONTEXT` block in the appropriate
  project `AGENTS.md` while preserving existing content and managed markers.
- Model choice, Astra/Luna role topology, session transfer, installation and
  publication remain owned by existing skills or explicit owner gates.

## Verification boundary

The candidate must pass the canonical validator, full deterministic test suite,
the three Codex-context probe fixtures, syntax checks, whitespace checks and a
release-gate review. A passing local probe proves only repository-level context
inventory behavior. It does not prove that a particular Codex client injected or
followed the discovered files; a fresh `codex debug prompt-input` or
`codex debug agents-md` readback is required for that claim.

checking the current working tree and rerun its validator and tests. The new
skill is additive; existing skill directories, aliases and adapters remain
unchanged.
