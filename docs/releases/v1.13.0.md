# v1.13.0 - skill doctor and evidence-bound fixes

This is the next-minor release candidate after the published `v1.12.0` source
release. It adds `nobrainer-skill-doctor` as the 17th portable skill inside
NoBrainer.Tech Flow. The doctor owns cross-project audits of skills, project
instructions and task prompts, including trigger overlap, excessive or
conflicting rules, coverage and minimal portfolio repair planning. It does not
replace Review's exact-change evidence gate or Codex-context's one-project
context setup boundary.

The candidate also carries accepted local fixes for uncertain session creation,
SDD state/template vocabulary, generic Security mode selection, Autoimprove
strict-cap lower bounds, Writing trigger scope and Browser local-first
capability discovery. Historical evaluation receipts remain internally
consistent with their original source bytes.

The bundled doctor inventory helper is read-only. It reports metadata and
candidate locations, records skipped symlink directories and traversal errors,
and does not establish semantic findings, client loading or model behavior.

## Verification boundary

Static and repository evidence for this candidate:

- 17 canonical skill directories and matching validator/installer/adapter
  inventories;
- 186/186 deterministic tests passed;
- both `scripts/validate_skills.py` modes passed;
- the helper inventory found 17 public `SKILL.md` files with `status: inventoried`
  and `skipped: []`;
- Python, shell and Node syntax checks passed;
- `git diff --check` and the configured Gitleaks scan passed;
- isolated temporary copy-install and source-archive readbacks passed.

These checks prove the reviewed source tree and local contracts only. Clean
client discovery, model behavior, client loading, marketplace distribution,
production behavior and user usefulness remain `UNVERIFIED` until each exact
client or external system supplies its own readback. No real client installation,
commit, push, tag or GitHub release is part of this candidate preparation.

## Rollback

Use the published `v1.12.0` source release as the rollback anchor. Restore only
the reviewed candidate files in an isolated checkout, preserve unrelated dirty
work and verify the previous 16-skill source and manifest state before any
client-side rollback.
