# nobrainer-tech-flow 2.6.0: delegate aggressively, verify by risk

Release date: 2026-10-23.

This release changes workflow guidance and the update line of the instruction block.
The setup record and the module set (eighteen) do not change.

## What changes

- **Aggressive delegation as the default.** `skills/nobrainer-tech-flow/SKILL.md` now opens
  substantial work with "Delegate aggressively": independent units run on parallel native
  subagents through team execution, and MAIN integrates, verifies and refills slots.
  `references/delivery.md` adds the reason (delegation is the default route to a faster
  done), keeps only tiny, tightly coupled, gated or shared-state steps in MAIN, and sets a
  cost rule: delegate a unit when parallel work shortens the time to done more than a
  worker's start-up costs, send a short task packet rather than the whole conversation,
  ask for a concise report, and give narrow, mechanical work to a cheaper model under the
  host's policy. No model is named.
- **Resend only failed units.** When part of a batch fails, only the failed units go out
  again with their new evidence; accepted units are not rerun.
- **Verification by blast radius.** `references/delivery.md` scales verification to how
  risky and reversible a change is. Reversible, low-risk changes may proceed on green
  automated tests, review and security checks. CI configuration, credentials,
  security-sensitive paths, data migrations and irreversible effects need an independent
  review and remain owner-gated. An agent's approval never counts as the owner's.
- **Two build rules.** `skills/nobrainer-build/SKILL.md`: before adding complexity for a
  speculative race or security edge case, name the concrete failure, its likelihood and
  the cost; and in user interfaces, taglines, helper text and secondary labels added to
  explain a screen count as slop, so the layout gets fixed instead.

## Daily updates by default, in one line

The managed instruction block now carries one short update line, on by default for new
setups: "Once a day on first use, update nobrainer-tech-flow to its latest verified stable
release from the canonical source, with a backup; change nothing else and ask if unsure."
`install_personalization.py --no-auto-update` writes the one-line opt-out instead ("tell
the owner when a newer stable nobrainer-tech-flow release exists; do not update it
yourself"); `--auto-update` stays accepted and means the default. With `--keep-options`
(which `install.py` and the guided setup always pass) the longer lines written before 2.6.0
become the matching short line: an old update grant stays a grant and the old notify-only
default stays notify-only, so no existing setup starts updating itself without a choice.
An update line that is neither recognized grant, for example one edited by hand, becomes
the notify-only line. `install.sh` follows the same rule when it refreshes an earlier block:
it rewrites the block in this version's text but keeps notifying unless the block held the
update line as its own line.

## Sources

The delegation rule is an owner decision (2026-10-23). The other rules were drawn from the
owner's recent X bookmarks and checked against the replies under each post; ideas that the
replies credibly disputed (a "canary" line to detect context decay, a viral prompt with a
false attribution) were left out.
