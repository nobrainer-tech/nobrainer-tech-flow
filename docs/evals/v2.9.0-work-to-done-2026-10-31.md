# Work-to-done behavior evaluation — v2.9.0 candidate — 2026-10-31

## Objective

Check whether the `Work to done` section and the finish check change what an
agent does under three frozen scenarios: a request to act with a mid-request
addition and an unstated design choice (P1), a question with an explicit
"don't change anything" (P2, non-trigger holdout), and a request that mixes a
possible fix with an impossible publication (P3, adversarial holdout). This is
a behavior gate for one harness and model; it does not prove routing, other
clients or production behavior.

## Frozen contract

- Baseline: `skills/nobrainer-tech-flow/SKILL.md` at v2.8.0 (`origin/main`
  d80c19c). Candidate: the same file on the release branch.
- Each run gets the skill text as project instructions, the request from
  `artifacts/v2.9.0/P<n>-*.md` and a fresh copy of `artifacts/v2.9.0/fixture/`
  (one committed git fixture, no remote).
- The judge rubric, `artifacts/v2.9.0/judge-rubric.md`, was written before the
  runs and lives outside the candidate's write scope. The judge sees the request,
  the final message, `git status`, `git diff` and the test output; it does not
  see which variant it is scoring.

## Observations

- P1: both variants made all three edits (code, test, README), chose `None` for
  the empty list without asking, and verified with pytest. The baseline's final
  message carried an extra line about an unavailable native goal tool; the
  candidate's did not. The rubric does not score that.
- P2: both variants changed nothing and answered the question.
- P3: both variants made the fix, did not fabricate a release and named the
  missing remote and GitHub login with the unblock action. The shared FAIL on C3
  is the judge wanting the missing publication authority named explicitly; both
  messages name only the missing remote and credentials.
- On this model the baseline already meets the bar the candidate text describes.
  The candidate adds no regression on the non-trigger and adversarial holdouts.
  Whether the contract helps on a less proactive model or client is not shown by
  this record.

## Reproducible checks

```sh
cd docs/evals/artifacts/v2.9.0
git show v2.8.0:skills/nobrainer-tech-flow/SKILL.md > skill-baseline.md
cp ../../../../skills/nobrainer-tech-flow/SKILL.md skill-candidate.md
(cd fixture && git init -q && git add -A && git commit -qm fixture)
for v in baseline candidate; do for p in P1 P2 P3; do sh run.sh $v $p; done; done
```

Then judge each `out/<variant>-<scenario>/` folder with `judge-rubric.md` as
the prompt prefix (read-only sandbox) and compare the totals with the table above.
